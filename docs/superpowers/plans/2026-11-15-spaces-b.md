# Cross-machine panes implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Each track has one writer in its own worktree. Do not dispatch reviewers per task.

**Goal:** Create terminals on any enrolled machine inside Mac-owned spaces, with correct close, park, reconnect, and remote-agent placement behaviour.

**Architecture:** Separate a real execution target from its Mac presentation. A local background presentation service owns durable visibility and target changes. Local agents remain native; attach proxies supply remote terminal interaction. Box endpoints authenticate against source-owned session state and launch views without box-side app placement.

**Tech Stack:** TypeScript, the existing Node runtime, Herdr mods and GPUI, hc, private JSON and Unix sockets, Vitest, and the existing packed Herdr acceptance framework. No new dependency.

**Spec:** `docs/superpowers/specs/2026-11-15-spaces-b-cross-machine-design.md`.

## Global constraints

- Target Herdr 0.1.13 and 0.1.16. Drop 0.1.14 from this feature's support and test matrix. If staging changes again tonight, the separate final compatibility task rechecks that staged bundle before release.
- No widening of the production look-patch version gate in B. The separate final compatibility task owns that change.
- B's live rollout is a maintainer sync. No writer edits live app state.
- The required move invariant is the same Mac space and tab. Local agents remain ordinary native panes; only remote terminals use Mac attach proxies. The pane ID need not stay the same. On unfocused 0.1.13 panes, defer conversion and retain the non-interactive "moved to <machine>; focus to reconnect" placeholder.
- Remote programs end only after spider-confirmed close intent. Unexplained proxy-process exit means Send back for shells and agents. An ambiguous attach-stream end means connection loss and reconnect, never park.
- A ships Cmd-Shift-W as `pane.close`; B owns and changes it to `spider-pane.close`. Native local behaviour, including pi confirmation, stays unchanged. B extends A's managed global key set with Cmd-T, Cmd-D, Cmd-Shift-D, and Cmd-Shift-W. A's Cmd-Shift-E stays layout-scoped `spider-pane.park`.
- Local machine text is always "This computer". Machine pills are neutral and immediately follow the session or run-name pill.
- Keep unit and non-process integration tests within 5000 ms. Run core and app stories serially with the existing acceptance deadlines.
- Files and sockets use mode 0600. Directories use 0700.
- Viewer minimum size is 60 columns by 8 rows. Display leases renew every five seconds and expire after 20 seconds.
- Refresh remote inventories on events and actions, with a five-second fallback while the UI is present. Single-flight per machine, bounded deadlines, and unreachable backoff prevent stacked cold starts. Batch lease renewals per machine. Pages contain at most 256 session rows and 1 MiB.
- Interactive proxies use the resolved absolute hc executable with `attach --history 100 <core-id>/<terminal-id>`, never a machine alias address. Verify core identity, terminal incarnation, and ownership before releasing input. Console proxies use `--observe`, which does not type or resize their targets.
- Disconnected proxies read and discard input in raw mode, flush queued input immediately before attach, and reset alternate-screen, mouse, bracketed-paste, kitty keyboard, and cursor modes before every attach, every status text, and exit, including a retarget that writes no status line. Task 0 must prove the packaged gated-TTY path.
- Reconnect delays are 1, 2, 5, and then 10 seconds, capped at 10 seconds. A newer binding resets backoff. Never restart shells, agents, children, or payloads to restore a pane. Subagent and console views are disposable and restart on reopen after lease expiry.
- No production app launch, focus, quit, or restart. No default-core stop or restart. No input is replayed into pi terminals.
- All public fixtures are synthetic. Example machines are `box-1.invalid` and `box-2.invalid`. Credentials and real-machine evidence stay outside the repository.
- Worktree writers do not share writable dependency directories, install dependencies, change another track's files, or push.

## Focus areas

1. A clicked split anchor changes focus or disappears while the picker is open. Task 2.1 must keep the original anchor or refuse without launch.
2. A routing alias is reused or a home epoch changes during a delayed close. Task 3.3 must not stop the successor target.
3. A foreground cwd differs from the terminal's starting cwd, or its mapped directory disappears. Tasks 1.1 and 4.2 must select the current directory or refuse explicitly.
4. The Mac closes the app or a view lease expires while a child is active. Tasks 3.2 and 5.1 must retain the child and avoid a hidden viewer process.
5. Multiple sessions share a name, or a remembered tab is deleted. Task 4.3 must keep the row unplaced and ask for a new Mac destination rather than choose a space silently.

Validation requires a connected machine to have a core identity. A disconnected configured row may lack one and still appears disabled. Session, subagent, and console targets require their session ID; subagent targets also require their run ID, and console targets require a source-validated `ConsoleId`. Parse the existing console key at the source boundary rather than casting it to a job ID. A legacy session target may have null generation until source facts verify it; that record cannot authorize close, viewer launch, or handoff. A local routing alias is null, not an invented machine named `local`.

Task 1.2 declares `PlacementState` as `{version: 2; revision: number; slots: LegacySlot[]; attempts: LegacyAttempt[]; presentations: PanePresentation[]; choices: ManualPaneChoice[]; launches: PaneTargetLaunch[]}`. `ManualPaneChoice` is `{session: SessionId; space: SpaceId; tab: TabId; revision: number}`. `PaneTargetLaunch` is `{operationId: string; coreId: CoreId; machineKey: string; intent: PaneOpenIntent; folder: FolderChoice; state: "claimed" | "not-started" | "uncertain" | "observed"; target: PaneTarget | null; failure: string | null}`. This separate claim is valid before hc allocates a terminal ID. Publish a complete presentation only after target identity is observed. Never invent a pending terminal ID. Copy the exact version-1 slot and attempt shapes from `roam-placement.ts`, including launch failure attempts and `localOwners`. Do not rename or discard them. `PanePlacementStore` exports `read(): Promise<PlacementState>` and `update(change: (state: PlacementState) => PlacementState): Promise<PlacementState>`. The store supplies locking and atomic replacement.

A live inventory row without hc registration has `owner: null`, `target: null`, and `unavailableReason: "not-in-hc"`. It retains session ID, generation, name, and machine identity for display. Such a row grants no open, move, close, or view authority. Source `Owner` fields remain private to the 0600 cache and are not copied into doctor output or public fixtures.

Task 3.1 declares `PaneServicePorts` in `service.ts`. It consumes the store, target/folder ports, an existing `HcClient`, an `AppClient | null`, a clock, and injected socket/process launch ports. It exposes no OS service installation or model API. `PaneService` has `request(input: PaneServiceRequest): Promise<PaneServiceReply>`, `reconcile(): Promise<void>`, and `stop(): Promise<void>`.

`PaneServiceRequest` and `PaneServiceReply` live in `types.ts`. Requests are version 1, have an operation ID, and are a tagged union of `snapshot`, `open`, `open-existing`, `open-auxiliary`, `move`, `park`, `close-confirmed`, `prepare-handoff`, and `present-ready`. `close-confirmed` carries the captured presentation revision and target incarnation; only the confirmed UI callback produces it. Unexplained exit events cannot synthesize that request. Mutations identify an existing presentation by ID and expected revision, or carry one validated creation intent and chosen machine key. `open-auxiliary` carries `{sessionId: SessionId; generation: Generation; view: {kind: "subagent"; runId: RunId} | {kind: "console"; machineKey: string}}`. The service resolves the real owner from validated inventory, reserves the owner's Mac slot, and invokes Track 5's source-owned view operations. Remote inventory exposes the real typed `Owner`, but never its IPC capability descriptor. Cache and render only the specified display fields. Replies contain either a bounded snapshot or a `PaneActionOutcome`. The snapshot includes display-only `targetFacts: Readonly<Record<string, PaneTerminalFacts>>`, keyed by core and terminal ID, populated with `readPaneTerminal` from verified source terminal snapshots. Header views read that projection rather than the proxy's Node cwd/title. Missing or stale facts keep the last verified display and never authorize a close. Raw target addresses, remote paths, and arbitrary argv are not mutation authority. Handoff inputs must pass injected source-owned generation and current-home validation before changing a binding.

Task 1.1 declares every `RemotePaneRequest` variant and reply codec in `types.ts`: `handshake {protocol, buildDigest}`, `list {cursor}`, `locate-folder {cwd}`, `resolve-folder {repoKey, workspaceId, relativeCwd}`, `launch-viewer {sessionId, generation, runId, leaseId}`, `renew-viewers {leases: {leaseId, generation}[]}`, `stop-viewer {leaseId}`, `open-console {sessionId, generation, machineKey, leaseId}`, and `close-session {sessionId, generation, homeEpoch, operationId}`. Each includes version 1. Folder replies distinguish no mapping, unavailable, and a mapped directory that no longer exists, with a source-local existence check. `RemotePaneReply` carries a handshake, portable folder identity, resolved folder facts, validated inventory page, target, or action outcome. Track 4 implements these existing declarations without reopening Track 1's files. Capabilities stay on the machine that owns its feed.
