# spider — Design Specification

> **Status:** Approved design (grilled Q1–Q23, 2026-07-02). Implementation gated behind the phased superplan in `docs/superpowers/plans/`.
> **Design history:** `/mnt/data/src/spider-design/grill-log.md` (living Q→Decision→Implications record).

## Product one-liner

**spider** (`guru-irl/spider`) is an all-in-one **pi coding-agent** extension — the "pi" hidden in *sPIder* — that unifies five existing codebases into one monorepo sharing a single SQLite database layer, and drives them as an **autonomic organism**: subsystems feed each other through the shared DB so memory, todos, context/search, and subagents co-evolve automatically.

The five unified codebases:
1. **pi-hermes-memory** (+ faithful TS ports of `hermes-agent` Python behaviors) → memory
2. **context-mode** → context/search (`ctx_*`)
3. **pi-todo-sqlite** → todos
4. **pi-subagents** → subagent orchestration
5. **superpowers** (customized `guru-irl/superpowers` fork) → skills

Plus one **external dependency** (not vendored): **pi-intercom** for realtime cross-session messaging.

---

## Guiding principles

- **P1 — Reuse Hermes maximally.** Hermes is tried-and-tested, AI-research-company-backed work. Reuse its code, behavior, and concepts as much as possible across ALL subsystems (not just memory). Code baseline = the pi-hermes-memory TS port, extended with faithful TS ports of `hermes-agent` Python behaviors. Prefer Hermes's proven choices over inventing new mechanisms.
- **P1a — The ONE intentional divergence: storage substrate.** Hermes is Markdown-as-truth; spider is **DB-as-truth**. Memory stores structured truth records that *link to* files/skills, never duplicating docs/commit-history content.
- **P2 — Pi-only, in-process.** No other coding tool, ever. Delete all non-pi adapters. Lift `ctx_*` out of the bridged server process into direct `pi.registerTool()` calls.
- **P3 — Cross-OS in-scope.** Everything is JS/TS; native deps ship prebuilt binaries. linux/mac/windows × x64/arm64.
- **P4 — Full-send defaults.** Route everything (universal tracking, no whitelist), hardened scanning, learning + autonomic cross-wiring ON by default, full tool access, **zero temp-dir usage** (all scratch to `.spider/scratch` / `~/.pi/agent/spider/scratch`), native pi-style UI for every command.

---

## Non-goals

- No support for any non-pi harness (Claude Code, Codex, Cursor, opencode, Gemini) — pi only, forever.
- No hardened sandbox/jail (full tool access is intentional).
- No multi-machine sync (single-machine; vector backend is local).
- No live upstream git merges — upstream tracking is a **review/cherry-pick** workflow (`upstream-watch`), not a merge.
- No memory→skill *promotion* pipeline (Hermes doesn't have one; see TC5).

## Architecture overview

### Monorepo (npm workspaces), one shipping unit

```
spider/
├── package.json                 # workspaces root; "pi" manifest; single extension entry
├── packages/
│   ├── db-core/                 # shared SQLite layer: schema, migrations, registry, driver, WAL/retry, sqlite-vec
│   ├── memory/                  # Hermes-port memory: records, categories, staging, threat scanner, snapshot, embeddings
│   ├── context/                 # context-mode lifted in-process: exec/exec_file/batch/index/fetch, content index, RRF search
│   ├── todo/                    # pi-todo-sqlite on shared DB
│   ├── subagents/               # pi-subagents runtime on shared DB (runs/run_events) + intercom orchestration
│   ├── superpowers/             # customized fork (v6.1.0 base, pi-only, spider-retargeted) — skills + AGENTS.md manager
│   ├── ui/                      # spider-ui: shared TUI kit + per-action renderers + footer + grid
│   └── host/                    # single pi extension entry: composes all subsystems, registers the `spider` tool, hooks, slash cmds, UI
└── docs/superpowers/{specs,plans}/
```

- **Dev:** npm workspaces for DX and clean internal boundaries.
- **Ship:** one esbuild bundle → **one published `spider` package** with a single `pi` manifest and a **single extension entry** (`host`). Internal packages compile into the ship artifact; native deps stay real `dependencies` so pi's `npm install` prebuilds them per-OS.
- **Distribution:** git-install `github.com/guru-irl/spider@ref` (primary), npm `@guru-irl/spider` (optional later).

### Two-tier DB topology

- **Global DB:** `~/.pi/agent/spider/spider.db` — cross-project registry, cross-project insights, global memory, upstream-watch refs, message mirror.
- **Per-project DB:** `<project>/.spider/project.db` — project-scoped memory, content index, todos, sessions, runs/run_events, events.
- **Projects registry (in global DB):** the single canonical resolver. `{ project_key, real_path, git_common_dir, db_path, created_at, last_seen_at, counts }`. **Kills context-mode #645** (hash-mismatch bug) because the global DB always knows where every per-project DB lives.
- **Driver:** **better-sqlite3** (synchronous, native). WAL mode + `busy_timeout` + retry wrapper (subagent child processes = multi-process access to the same DB files).
- **Project key:** `git rev-parse --git-common-dir` → **worktrees share state**. Non-git dirs key on real path.
- **Session id:** pi's native id verbatim; subagent children carry `parent_session_id`.

### Paths (P4: zero temp-dir)

- **Global root:** `~/.pi/agent/spider/` → `spider.db`, `scratch/`, `models/` (embedding models), `logs/`, `config.json`.
- **Per-project root:** `<project>/.spider/` → `project.db`, `scratch/`, `logs/`, `config.json`, `skills/` (**committed**).
- **Auto-written `.spider/.gitignore`** ignores `project.db*`, `scratch/`, `logs/`, `config.json` — but **`.spider/skills/` is committed** (AI-authored project skills travel with the repo).

## The `spider` mega-tool surface

Single two-layer tool named `spider`. Everyday verbs in the `action` enum; admin under `action:"control"` with a `command` naming the sub-command. All ~20 legacy tools (`memory`, `skill_manage`, `session_search`, `memory_search`, `todo`, `subagent`, `wait`, 11× `ctx_*`) collapse into this one tool. pi built-ins `edit`/`write` are overridden for tracking (see Routing); everything else is replaced.

### `action` enum (everyday verbs)

| action | purpose |
|--------|---------|
| `search` | unified hybrid FTS+vector search across memory/content/sessions/todos |
| `remember` | write a memory record (staged if `[auto]`/background) |
| `recall` | fetch memory records (category/scope filtered) |
| `exec` | run a command in-sandbox, print-only (context-mode `ctx_execute`) |
| `exec_file` | run code over a named file (context-mode `ctx_execute_file`) |
| `batch` | run multiple commands + inline queries (context-mode `ctx_batch_execute`) |
| `index` | index a file/dir into the content KB (context-mode `ctx_index`) |
| `fetch` | fetch+index URLs (context-mode `ctx_fetch_and_index`) |
| `run` | spawn subagent(s) — single/chain/parallel/async, pipeline w/ intercom handoff |
| `wait` | await subagent runs |
| `todo` | todo CRUD (list/add/toggle/clear/sessions/view) |
| `skill` | skill ops incl. `/learn`-style distill-from-conversation |
| `import` | ingest session(s) → organism digest → staged candidates + index + embed |
| `message` | cross-session message (thin wrapper over pi-intercom dep) |
| `control` | admin layer (below) |

### `control` sub-commands (admin)

`stats`, `doctor`, `purge`, `upgrade`, `insights`, `switch-project`, `registry`, `upstream-watch`, `memory` (pending/approve/reject/consolidate), `skill curate`, `config` (get/set), `grid`, `migrate` (alias of top-level `import`), `reembed`.

### Slash commands

`/spider`, `/todos`, `/memory`, `/search`, `/agents`, `/insights`, `/learn`, plus thin `/doctor` `/stats` `/upgrade` `/purge`.

### Hotkeys

- Persistent **agents footer** above the chat bar (visible when ≥1 agent active).
- **Ctrl+G** toggles the live agents grid. In-grid: arrows focus, Enter drills full-screen, Esc closes; action keys `m` (message/wake), `i` (interrupt), `r` (resume), `f` (follow/pin).

## Subsystem: Memory (Hermes port, DB-as-truth)

### Model

- **THE DB IS THE TRUTH** (P1a). No `MEMORY.md`/`USER.md`/project-memory Markdown. Memory stores **structured truth records** that **link to** files/skills; never duplicates docs or commit-history content.
- **Category taxonomy:** `preference`, `convention`, `tool-quirk`, `failure`, `correction`, `insight`. Anti-poisoning guardrails retained from Hermes.
- **Overflow = hard-reject**, never silent drop. Auto-consolidate is an explicit, model-invokable tool (`control memory consolidate`), not automatic on overflow.
- **Frozen snapshot:** assembled from DB at session start, char-capped, injected via `before_agent_start` (TC6). Writes persist immediately but re-inject next session.
- **Write-approval staging:** ON by default, **fail-closed**. All `[auto]`/background writes are staged; approve/reject via `control memory pending|approve|reject`.

### Hermes-agent behaviors to port (faithful TS)

- **Hardened threat scanner** (from BOTH real `hermes-agent` and the pi port): scope tiers, NFKC folding, ReDoS-safe bounded-filler, streaming-safe scrubber, secret/injection detection.
- **Background-review anti-poisoning** guardrails.
- **Aux-model digest routing** (3–5× cheaper model for digests/self-naming).
- **External `MemoryProvider` interface** (pluggable memory backends).
- **Memory↔skills relationship (TC5, faithful-Hermes, no promotion loop):** the organism pass = Hermes `background_review` — decides **memory vs skill per learning** and writes **both** as staged `[auto]` candidates (co-equal capture). Plus a **skill curator** (decay + umbrella consolidation, respect pins, protect builtins/hub, never auto-delete) at session-end + min-interval (~24–48h) + manual `control skill curate`. Plus `/learn` (distill a skill from the conversation) and a **learning graph** (skills↔memory nodes) feeding `control insights`.

## Subsystem: Embeddings + unified search

- **Default embedder:** `fastembed-js` (onnxruntime-node) + **BGE-small-en-v1.5** (384-dim). Fast native inference, strong quality, self-contained; model lazily cached to `~/.pi/agent/spider/models/`.
- **Optional providers (pluggable):** copilot / openai / mistral / google via pi creds (TC2 — spider owns the embedding HTTP call). Not default.
- **Fallback chain:** onnxruntime → transformers.js (WASM, exotic platforms) → **FTS-only** (offline/no-embeddings degrade gracefully).
- **Storage:** **sqlite-vec** (`vec0` KNN in the shared DB) + brute-force JS cosine fallback.
- **What gets embedded:** memory records + content chunks; sessions/runs via projected chunks; todos are FTS-only.
- **Background embed queue:** default-on; degrade to FTS if unavailable.
- **Hybrid search:** FTS + vector fused via **RRF** (reuse context-mode's fusion). `provider + model + dim` recorded in config; dims are index-locked → `control reembed` migrates on change.

## Subsystem: Model selection & routing (`@spider/models`)

Agents intelligently use the **full model suite** available (especially GitHub Copilot's range), instead of a single fixed model. (TC8: `getModel(provider,id)` + `streamProxy`/`complete` for invocation; `GITHUB_COPILOT_MODELS` ∩ creds `availableModelIds` for the catalog; per-subagent `task.model` already first-class.)

- **Catalog discovery:** enumerate available models = `GITHUB_COPILOT_MODELS` filtered by the Copilot OAuth creds' `availableModelIds`, plus any other configured providers (`~/.pi/agent/models.json`, anthropic/openai/etc.). Each entry enriched with `{ provider, id, tier, reasoning, vision, ctx, speed, costHint }`.
- **Tiers** (derived from id heuristics + capability flags + config override map — NOT hardcoded ids, since they drift): `nano` → `mini` → `standard` → `capable` → `reasoning`.
- **`pick(profile)`** → the best *available* model for `{ role, complexity, needsReasoning, needsVision, budget, thinkingLevel }`. Precedence: explicit override > config default (per-role/per-kind) > policy. Only picks from actually-available models; degrades down a tier if the target is unavailable.
- **Shared `complete(model, prompt, opts)`** helper (wraps `getModel` + `streamProxy`) = the single place spider runs its own aux completions (memory/organism digests, self-naming, upstream-watch summaries). Resolves the "how do we call a model" seam. Exempt from agent-facing routing.
- **Consumers:** subagent `run` auto-selects per task unless the caller passes `model` (reviewer/next-phase workers → `capable`/`reasoning`; mechanical/parallel workers → `nano`/`mini`); memory + organism digests + self-naming → cheap tier; the embedding provider stays in the `embeddings` config group.
- **Autonomic tie-in (lightweight v1):** capture `model_stats` (latency, success, token-cost) in the DB; the organism uses them to break ties and avoid recently-failing models. Fuller learned routing is a later enhancement.
- **Superpowers/AGENTS.md (Phase 7)** carries prompt guidance so the MAIN agent also chooses models intelligently per subagent task (automated router + guided prompting).

## Subsystem: Context (context-mode lifted in-process)

- Delete all non-pi adapters (>60% of context-mode LOC). Lift `ctx_*` out of the bridged server process into direct `pi.registerTool()` calls: `exec`, `exec_file`, `batch`, `index`, `fetch`.
- Content index + auto-index of large tool outputs (from Routing). Hybrid FTS+vector RRF feeds unified `search`.
- Keep WAL + busy_timeout/retry (multi-process safety).

## Subsystem: Todo (pi-todo-sqlite on shared DB)

- Port todo CRUD onto the shared per-project DB. Per-project + per-session scoping preserved (`list`/`add`/`toggle`/`clear`/`sessions`/`view`). FTS-only (no embeddings). Feeds `todo→memory` organism pass.

## Subsystem: Subagents runtime + intercom orchestration

- Port pi-subagents `run`/`wait` (single/chain/parallel/async, forked context) onto the shared DB: **`runs` + `run_events` tables** (replaces tmpdir JSON/JSONL; persists across restarts; feeds footer/grid/organism/search).
- **Intercom = external dependency** (`pi-intercom`, realtime Unix-socket broker). NOT vendored, NOT reimplemented.
- **Value-add = auto-wake worker chaining:** a finishing worker uses intercom to **wake the reviewer / next-phase workers with its outputs directly**, replacing the blocking `spawn → wait → process → spawn-next` cycle. Push-based multi-phase pipelines.
- **OPEN sub-decision (resolve in Phase 4 plan):** pipeline-with-handoff as a first-class `run` construct (`run {pipeline:[...], handoff:"intercom"}`) vs purely prompt-driven.
- `message` verb = thin wrapper over pi-intercom; message events mirrored into the shared DB for observability only (live traffic stays on the socket).

## Subsystem: Subagents UI (footer + live grid)

Replaces the current subagents UI wholesale. Current defects: rebuilds the whole widget subtree every frame (no diffing), 250ms poller, `JSON.stringify` change-detection over ~22 fields.

**New architecture:** event-driven store → coalesced frames → diff → paint.

- **Data source:** shared DB `runs`/`run_events` (single event stream).
- **Footer** (above chat bar, visible when ≥1 agent active, hidden at zero): per agent = status glyph + self-name/role + elapsed + current activity (tool/phase) + step/token count; overflow beyond ~4 aggregates (`▸ 4 running · 2 done · +3 more`).
- **Update model:** event-driven on DB append (in-process emitter), coalesced ~16–33ms frames, line-diffed repaint. No polling.
- **Grid (Ctrl+G) scaling:** 1→full, 2→1×2, 3–4→2×2, 5–9→3×3, 10–16→4×4, >16→4×4 paginated. Cell = header (name/role/status/elapsed) + tail of recent activity + progress.
- **Interaction:** arrows focus, Enter drills full-screen, Esc returns; keys `m`/`i`/`r`/`f`.
- **Pipeline-aware from the start:** footer/grid visualize handoff edges + phase state (worker→reviewer auto-wake).

## Subsystem: Autonomic organism

- **Triggers: `session_before_compact` + `session_shutdown` ONLY** (TC4). No turn-timer, no per-event digest. Event log records continuously; the organism drains/digests at those two points (rescue-before-summarize + final consolidation).
- **Passes (all default-on, master + per-behavior toggles):**
  1. `run → memory/todo`
  2. `todo → memory`
  3. learning loop (failures/corrections, anti-poison filtered)
  4. session consolidation + **self-name update**
  5. reflection/synthesis (vector clustering → umbrella memories)
  6. cross-project insights graph
  - The organism pass = Hermes `background_review`: may write **both** staged memory AND staged skill candidates (co-equal per TC5).
- **Self-naming sessions:** each session names/renames itself from the broad ongoing task via aux-model digest.
- **Guardrails:** cheap aux-model, single in-process background worker, per-session auto-write budget, all auto-writes `[auto]`-staged (fail-closed).
- **upstream-watch:** command-driven (not automatic). **Content-freshness:** lazy-on-search.

## Routing / safety layer (universal tracking OVER pi's native tools)

- **No whitelist, nothing blocked.** Spider is a tracking + safety layer, not a block+force gate.
- **`beforeToolCall`** (TC1 — deny+message only, cannot rewrite args): records tool intent to the DB event log.
- **`afterToolCall`** (TC1 — can fully replace results): runs Hermes secret-scrub + injection-scan + large-output auto-index.
- **`edit`/`write` override** (TC3 — same-name registration inherits pi's native renderer): adds a required 1-line `description`; tracks `{description, +N/-N lines}` (NOT full diff — inherits pi's native diff renderer).
- **Single event stream, three consumers:** organism learning loop + subagents footer/grid + tracking.
- Spider's own service calls (embeddings, digests) are exempt from agent-facing routing.

### AGENTS.md delivery (TC6)

- **Static preamble** (spider-flavored `using-superpowers` content + tooling/memory discipline) = **spider-managed delimited block** (`<!-- spider:start -->…<!-- spider:end -->`) in global `~/.pi/agent/AGENTS.md`, rewritten idempotently on install/upgrade. **Replaces the current five-tool guide.** User content outside the block is preserved.

- **Token budget:** today ≈ ~2.7K always-on (AGENTS.md ~1.4K + using-superpowers ~1.3K). Target ≈ 1.5–2K for the single lean spider block → net token win.

## Session import

- **`action: "import"`** (top-level, agent-callable) + `control migrate` alias. Not an auto one-time DB import — a **session-import command**.
- **Per session:** read transcript → run the organism digest pass (aux-model) → **staged** memory/skill/todo candidates + index session for search + embed. Idempotent via imported session-ids in the registry (re-import merges, never dupes).
- **Input shapes:** `{session}` | `{sessions:[...]}` | `{select:{project?,all?,since?,glob?}}`.
- **Source:** pi session files (primary); old hermes/todos/context-mode DBs = optional source mode (manual, never automatic).
- **Staged by default**; opt-in `commit:true` for trusted single imports. Designed for a subagent to fan out over many sessions.

## Config & observability

- **Precedence:** built-in defaults < global `~/.pi/agent/spider/config.json` < project `.spider/config.json` < env overrides. Edited via `control config get|set` (+ UI picker), file hand-editable. **Format = plain JSON.**
- **Schema groups:** `organism` (master + per-behavior toggles, default-on), `embeddings` (provider/model/dim, queue, reembed), `memory` (auto-write budget, staging fail-closed, snapshot char-cap, categories), `routing` (tracking, secret-scrub, injection-scan, auto-index threshold), `curator` (min-interval), `self_naming` (on/off, aux-model), `models` (catalog/tier overrides, per-role/per-kind defaults, budget caps, auto-select on/off), `ui` (footer on/off, grid hotkey, theme).
- **Observability:** structured JSON logs to global + project `logs/`; `control doctor` (native deps load, DB health/migrations, sqlite-vec load, embedding-provider reachability, registry integrity); `control stats` (token savings, row counts); `control insights` (learning graph).
- **Runtime toggles:** hot-reload via `resources_discover` reload; restart only for embedding model/dim change.

## Technical constraints (ground-truth, source-verified)

- **TC1 — pi hook contract.** `beforeToolCall(ctx) => {block?, reason?}` — deny+message only, CANNOT rewrite args/substitute result. `afterToolCall(ctx) => {content?, details?, isError?, terminate?}` — CAN fully replace any executed tool result. Hooks fire for built-in tools AND in subagent child processes; multiple extensions chain.
- **TC2 — embeddings.** No public `pi.embed()`. pi ships github-copilot OAuth + bundles OpenAI/Mistral/Google SDKs → spider OWNS the embedding HTTP call reusing pi creds; spider's own service calls are exempt from agent-facing routing.
- **TC3 — built-in tool override.** Extensions override built-ins (`read`/`bash`/`edit`/`write`/`grep`/`find`/`ls`) via same-name `pi.registerTool()`; omitted `renderCall`/`renderResult` inherit the built-in renderer. `--no-builtin-tools` and `getTool()` exist.
- **TC4 — compaction/session events.** `session_before_compact` (before summarizing, CAN cancel/customize, `reason: manual|threshold|overflow`), `session_compact` (after, carries `compactionEntry` + `reason` + `willRetry`), `session_shutdown` (teardown: quit/switch/resume/fork), `session_start` (`{reason: startup|new|resume|fork, previousSessionFile?}`).
- **TC5 — Hermes memory↔skills.** NO promotion pipeline. `background_review.py` picks memory OR skill per turn (co-equal); `curator.py` = skill lifecycle (decay + umbrella consolidation, 168h inactivity); `/learn` distills a skill from the conversation; `learning_graph.py` links skills+memory nodes. pi port is more conservative (background review = memory only).
- **TC6 — instruction/system-prompt contribution.** `before_agent_start` hook: `event.systemPrompt` is the chained prompt (append via return); `event.systemPromptOptions` exposes custom prompt, tools, snippets, **loaded AGENTS.md context files**, skills; `ctx.getSystemPrompt()` also available. pi auto-loads AGENTS.md files as context.
- **TC7 — packaging & native modules.** pi runtime = Node (`engines node>=22.19.0`), NOT Bun. `pi install` accepts `npm:` | `git:` | URL | path; runs `npm install` on install (native deps prebuild/compile; `postinstall` runs). Manifest = `package.json` `"pi"` key + `pi-package` keyword. Precedent: context-mode ships better-sqlite3 + esbuild bundle + postinstall + assert-bundle; pi-hermes-memory ships better-sqlite3.
- **TC8 — model catalog + completion.** Extensions get model handles via `getModel(provider, id)` (`@earendil-works/pi-ai`) and run completions via `streamProxy(model, context, options)` / `complete`/`generate`; `listModels`/`availableModels`/`currentModel`/`resolveModel`/`setModel` surfaces exist. Per-subagent model is first-class (`task.model`, `defaultModel`, `parentModel`, `{model, thinkingLevel}` branch overrides). Copilot catalog = `GITHUB_COPILOT_MODELS` gated per-user by OAuth creds `availableModelIds`.

## Global constraints (apply to every task in every plan)

- **Language:** TypeScript, Node ≥ 22.19.0 (target Node 24). ESM (`"type": "module"`).
- **SQLite driver:** better-sqlite3 (synchronous). WAL + busy_timeout + retry wrapper everywhere DB is opened.
- **Native deps (prebuilt, cross-OS):** better-sqlite3, sqlite-vec, onnxruntime-node (via fastembed-js).
- **Zero temp-dir:** all scratch/intermediate/golden data under `.spider/scratch/` (project) or `~/.pi/agent/spider/scratch/` (global). Never `/tmp`, `$TMPDIR`, `/var/tmp`.
- **Bundler:** esbuild; externalize native `.node`. Single extension entry from `host`.
